PHASE 1 MVP — Minimum Buyable Product 0-2.5 months · 2-3 engineers
What you're building: The smallest slice of Nxance that a real user will pay real money for. Not a demo — a thing someone pulls out their card for.
[ ]
Auth — Phone OTP login via Supabase Auth. That's it, no MFA, no biometric yet.
[ ]
Portfolio input — CAS PDF upload, parsed with the open-source casparser library. No live data sync yet.
[ ]
4 Health Check sub-engines — Performance (XIRR/Sharpe), Cost Leak (TER waste), Goal Alignment (future value gap), Structure (concentration risk). Plain Python, no Rust yet.
[ ]
AI translation layer — Self-hosted TinyLlama 1.1B on a rented GPU, turns the 4 sub-engines' raw output into plain-English issue cards.
[ ]
Payment — Razorpay one-time payment link, Rs.49-99, to unlock the full report. This is the actual test, so it can't be skipped or deferred.
[ ]
Frontend — Next.js web app only. No mobile app at this stage.
What You're NOT Building Yet
—
Construction Engine (any of it), the other 7 Health Check sub-engines, mobile app, admin panel, Rust/C++/CUDA, Account Aggregator, own cloud, real NxanceLM model
Definition of Done: 50+ real users uploaded a real portfolio. 15%+ paid for the full report with their own money. AI-generated text checked for accuracy on 30+ samples, zero hallucinated Rs. figures.
PHASE 2 Beta — Full Diagnostic + Construction Begins 3-6 months · 4-5 engineers
What you're building: The complete diagnostic engine (all 11 sub-engines), live consent-based data instead of manual upload, the first half of the portfolio-builder engine, and a real mobile app.
[ ]
Remaining 7 Health Check sub-engines — Fraud Gate (7 hard rules + ML anomaly model), Behaviour, Tax Efficiency, Forecasting (Monte Carlo), Liquidity, ESG/Suitability, Peer Comparison. All 11 now live.
[ ]
Account Aggregator integration — Register as FIU with RBI, integrate an AA gateway (Setu/Anumati), replace manual CAS upload as the primary onboarding path.
[ ]
Selection Engine (basic) — 4-6 of its eventual 12 scoring layers. Suggests alternative funds, no QAOA yet.
[ ]
Construction Engine — first 6 sub-engines — Profile Engine, Goal Decomposer, Constraint Builder, Asset Allocation, Universe Filter, Selection Bridge. Classical portfolio-building logic, no quantum yet.
[ ]
Mobile app — React Native + TypeScript. Home, Portfolio, Settings, Profile screens.
[ ]
Subscription billing — Rs.199/month recurring via Razorpay, not just the MVP's one-time payment.
[ ]
Backend split begins — Monolith splits into User Service + HC Engine Service + Construction Engine Service (still all Python).
What You're NOT Building Yet
—
Construction sub-engines 7-14 (correlation, QAOA, tax optimiser, stress-test), real trained AI model, Rust/C++/CUDA rewrite, full admin panel, own cloud live
Definition of Done: 1,000 users, all 11 HC sub-engines validated against 50+ manually-checked portfolios. 100+ paying subscribers. AA onboarding shows measurably lower drop-off than manual PDF upload.
PHASE 3 Phase 1 — Production Platform 7-12 months · 8-10 engineers
What you're building: Every engine complete to full scope, real AI (not TinyLlama), self-hosted infrastructure, and the operational software your business team runs on.
[ ]
Remaining 8 Construction sub-engines — Cross-Asset Correlation, MVO, QAOA (GPU-simulated quantum optimisation), Tax-Aware Optimiser, Backtesting (5 historical crashes), Regime Stress-Test, SIP Designer, Rebalance Scheduler. All 14 now live.
[ ]
NxanceLM v1 — real hybrid AI — Train from scratch: Transformer attention + Mamba (State Space Model) layers, 7B params, 32K context. Replaces TinyLlama entirely. PyTorch + DeepSpeed + mamba-ssm CUDA kernels.
[ ]
Rust Calc Engine — XIRR/Sharpe/CVaR/correlation rewritten in Rust (Axum+Rayon), called from Python via PyO3. 10-50× faster.
[ ]
C++ optimisation core — MVO (Eigen library) handles the full 7,400-instrument universe in production.
[ ]
Own cloud goes live — Self-hosted Postgres (Patroni HA) on Ohshn Cloud (OpenStack+Ceph), full cutover from Supabase.
[ ]
Admin panel — all 6 departments — Construction, Sales, Operations, Issue Resolution, Investment/R&D, User Relations. Full RBAC + audit logging.
[ ]
Formula version control — Git-style versioning for all 25 sub-engine formulas, A/B testing framework for the R&D team.
What You're NOT Building Yet
—
MoE sparsity layer for NxanceLM, real quantum hardware (still GPU-simulated), multi-city cloud, B2B API products, on-device AI
Definition of Done: 10,000 users, Rs.20L+ MRR. All 25 sub-engines live. NxanceLM v1 matches/beats TinyLlama quality at a fraction of per-query cost. Own cloud at 99.9% uptime for 60+ consecutive days.
PHASE 4 Full Final — Scale + Frontier Tech 13-24 months · 15-20 engineers
What you're building: The frontier upgrades — smarter AI at scale, real quantum hardware, offline capability, and turning internal infrastructure into products you sell to other companies.

[ ]

[ ]
On-device AI — Distilled NxanceLM via ONNX Runtime Mobile / TensorFlow Lite, runs offline for poor-connectivity users.
[ ]
Multi-DC cloud — Ohshn Cloud expands Mumbai → Delhi NCR + Chennai, active-active replication.
[ ]
B2B products — Ohshn Cloud (VM/storage/DB/AI APIs), OhshnQuantum API (QAOA/Grover/VQE), NxanceLM API — all sold externally to other companies.
Definition of Done: 1,00,000+ users, Rs.2Cr+/month combined B2C+B2B MRR. NxanceLM v2 outperforms v1. QAOA on real QPU demonstrably beats classical MVO in production. 5+ paying B2B enterprise customers.
The One Rule
Never Build Ahead of the Metric
This is the single most important thing for a technical team to internalise about this roadmap.
Every phase exists to prove one specific thing before the next phase's spend is justified. Building Rust/C++/CUDA before MVP proves anyone will pay wastes engineering time optimising a product nobody wants. Building real quantum hardware access before Phase 1's 10,000 users wastes crores on precision nobody will notice at small scale. If an engineer on the team suggests "let's just build it properly from the start" — that instinct is usually wrong here. Each phase earns the right to build the next by hitting its number first.
