Step 1 — Portfolio Input Methods

Method A — CAMS / KFintech OAuth

User logs in with CAMS/KFintech credentials. API returns all MF holdings with purchase date, NAV, units, invested amount. Fastest method. Covers all mutual fund holdings automatically.

Method B — Account Aggregator (RBI AA Framework)

User gives one-time consent. AA fetches bank accounts, demat holdings, MF portfolios from all linked financial institutions. Most comprehensive — covers all asset classes.

Method C — CAS PDF Upload

User uploads Consolidated Account Statement PDF (from CAMS/KFintech). pdfplumber library parses the PDF. Extracts fund names, units, NAV, invested amount, purchase dates.

Method D — Excel / CSV Upload

User uploads their own spreadsheet. Required columns: Fund Name, Current Value, Invested Amount, Plan Type. Optional: Purchase Date, TER. pandas parses and validates.

Method E — Photo / Screenshot

User takes photo of portfolio screen (any app). Tesseract 5.0 OCR + Vision AI extracts text. Numbers and fund names parsed automatically. NxanceLM validates extracted data before analysis.

Method F — Manual Entry

User types fund name + current value + invested amount. Works for any asset class. Most flexible — no login required with any other service.

Step 2 — The 14 Analysis Parameters

All 14 run simultaneously using Python asyncio.gather() — not one by one. Total analysis time: 3–8 seconds.

1
XIRR — Annualised Return (scipy.brentq)
What: Exact annualised return accounting for timing and size of every investment.
Why: Simple return % lies — 30% over 5 years = 5.4%/year. XIRR shows the real number.
How: Newton-Raphson method using scipy.optimize.brentq. Same algorithm as Excel XIRR.
Output: X% per year vs 4 benchmarks (Nifty 50, Nifty 500, Category Average, FD Rate).
Weight in health score: 25%
2
Sharpe + Sortino Ratio
What: How much return per unit of risk taken.
Formula: Sharpe = (Portfolio Return − Risk Free Rate) / Annual Volatility. Risk free = SBI FD 6.8%/year.
Sortino: Like Sharpe but only penalises downside volatility (more relevant for investors).
Output: Ratio with interpretation (Below 0.5 = poor, 0.5–1.0 = ok, 1.0+ = good).
3
Jaccard Fund Overlap Detection
What: How many common stocks exist between fund pairs. Identifies hidden duplication.
Formula: Jaccard = |A ∩ B| / |A ∪ B| where A and B are top-30 holdings of two funds.
Data source: AMFI holdings data (updated monthly) via mfapi.in.
Output: Overlap % per fund pair + annual ₹ waste = overlap_ratio × portfolio_value × TER_difference.
Example: Axis Bluechip + Mirae Large Cap = 62% overlap → ₹4,800/year waste on ₹5L portfolio.
4
HHI — Concentration Index
What: Herfindahl-Hirschman Index measures portfolio concentration.
Formula: HHI = Σ (weight_i)² × 10,000. HHI above 2,500 = highly concentrated.
Output: Concentration score + specific holding causing concentration risk.
5
Jensen's Alpha + Beta
Alpha: Excess return above what CAPM predicts given portfolio's beta.
Beta: How much portfolio moves relative to Nifty 50. Beta = 1.0 = moves exactly with market.
Interpretation: Positive alpha = fund manager adding value. High beta + low return = bad risk-reward.
6
CVaR — Conditional Value at Risk (3 Methods)
What: In the worst 5% of scenarios, expected average loss. More conservative than VaR.
Method 1: Historical — uses actual past return distribution.
Method 2: Parametric — assumes normal distribution, faster computation.
Method 3: Monte Carlo — 10,000 simulated paths, most accurate.
Crisis simulation: Also tests portfolio against 2008 crash, 2020 COVID crash, 2013 taper tantrum scenarios.
Weight in health score: 20%
7
Goal Gap — Monte Carlo Simulation (10,000 paths)
What: Probability of achieving user's financial goal given current portfolio + SIP.
How: numpy.random.normal() generates 10,000 possible market return sequences. Each path simulates portfolio value at goal year.
Output: Success probability %. If below 60% — calculates extra monthly SIP needed for 75% probability.
Example: "Retirement goal ₹50L by 2044 — only 38% probability. Add ₹3,200/month SIP to reach 75%."
Weight in health score: 15%
8
Regular vs Direct TER Waste
What: Exact rupees wasted per year in Regular plans vs Direct plans.
Data: TER for every fund from AMFI (updated daily). Regular TER avg 1.2–1.7%, Direct avg 0.3–0.7%.
Calculation: Waste = portfolio_value × (regular_TER − direct_TER) / 100.
10-year compound effect: Also shows how much this compounds to over 10 years assuming 12% CAGR.
Weight in health score: 20%
9
Macro Sensitivity Analysis
What: How sensitive is the portfolio to 10 macroeconomic factors.
Factors: RBI repo rate, CPI inflation, USD/INR, crude oil price, US Fed rate, gold price, India GDP growth, FII flows, global VIX, India VIX.
Method: Correlation analysis between each holding's returns and each macro factor.
Output: "Your portfolio is 78% sensitive to RBI rate changes — high interest rate risk."
10
News Sentiment Analysis (FinBERT)
What: Sentiment of recent news about each holding in user's portfolio.
Model: FinBERT — BERT fine-tuned on financial news. Classifies each news item as positive/negative/neutral.
Data source: Financial news APIs (Moneycontrol, ET, Mint) — last 30 days.
Output: Sentiment score per holding. Alert if negative sentiment spike on any significant holding.
11
Fraud + Governance Screening
What: Red flags for fraud, governance issues, regulatory problems.
Checks: SEBI enforcement database (active show cause notices, bans) · Promoter pledge % (high pledge = red flag) · Related party transactions · NSE/BSE surveillance list · Auditor resignation history · High debt companies with falling revenue.
Output: Warning flags per holding with severity level.
12
Liquidity Assessment
What: How quickly can each position be liquidated if needed.
Factors: Average daily trading volume (stocks/ETFs) · Exit load period (MFs) · Lock-in periods (ELSS, SGBs) · Real estate (illiquid by nature).
Output: Liquidity score + days to liquidate each position + total liquid vs illiquid % breakdown.
13
Investment Pattern Analysis
What: How portfolio allocation aligns with user's stated financial goals and time horizon.
What is checked: Asset allocation vs goal type (retirement = more equity, short-term = more debt) · Age-appropriate allocation (100-minus-age rule as baseline) · SIP consistency pattern · Portfolio drift from target.
Output: "Your allocation is 85% equity but your goal is 4 years away — consider reducing equity for capital preservation."
14
Rebalancing Signal
What: Has the portfolio drifted from its target allocation due to market movements.
Threshold: If any asset class drifts more than 5% from target → rebalancing recommended.
Output: Specific rebalancing actions — sell X amount of A, buy Y amount of B — with tax impact calculation.

Section 04 — Product 2
Portfolio Construction — How It Works
From 5 user answers to a mathematically optimised, backtested, NxanceLM-explained portfolio. Every step explained.

Step 1 — User Profiling (5 Questions)

Q1 — Goal: Retirement / Buy House / Child Education / Wealth Creation / Emergency Fund. This determines time horizon expectation and withdrawal pattern.

Q2 — Time Horizon: Slider from 1–30 years. Most critical variable. Under 3 years = equity cap 30%. Over 7 years = full asset universe available.

Q3 — Monthly Investment: Exact ₹ amount. Determines SIP per instrument. Also determines which asset classes are accessible (under ₹50K = MF only, over ₹5L = direct stocks, SGBs, REITs open).

Q4 — Risk Comfort: "If your portfolio drops 20% tomorrow, what do you do?" Options: Sell everything (Low) / Slightly worried (Medium) / Buy more, it's a discount (High). This sets maximum equity allocation hard limit.

Q5 — Existing Savings: Current savings for this specific goal. Starting value for Monte Carlo projection.

Output: User Profile Vector = {goal, years, monthly_₹, risk_level, existing_₹}. This vector drives all optimization constraints.

Step 2 — Asset Universe Filtering

Based on profile, eligible asset classes are determined:

Time HorizonRisk LevelMax EquityAvailable Assets
Under 3 yearsLow30%FD, Debt MF, Short Duration, Gold
3–5 yearsMedium55%Above + Large Cap MF, Index Fund, SGBs
5–7 yearsMedium70%Above + Flexi Cap MF, International MF
7–10 yearsHigh85%Above + Mid Cap MF, Stocks, ETFs
10+ yearsHigh95%Full universe — all 14 asset classes

Step 3 — 7-Layer Instrument Analysis

Every eligible instrument in the universe is scored across 7 layers before entering the optimizer:

Layer 1 — Macro: How does this instrument behave in current macro environment? (RBI rate cycle, inflation, growth phase). Instruments that benefit from current macro get higher score.

Layer 2 — Fundamental: For stocks/equity MFs — P/E ratio, P/B ratio, ROE, earnings growth, debt levels. Quality scoring using Piotroski F-Score.

Layer 3 — Technical: RSI (momentum), MACD (trend), 50-day vs 200-day moving average, support/resistance levels. Relative strength vs benchmark.

Layer 4 — Sentiment: FinBERT NLP on last 30 days of news + social media sentiment. Negative sentiment = lower score, positive = higher.

Layer 5 — Quantitative: Factor model scores — quality, value, momentum, low volatility. Based on academic factor investing research (Fama-French).

Layer 6 — Fraud Check: Same as health check engine. Any fraud flag = instrument removed from universe completely before optimization.

Layer 7 — Position Sizing: Tax implications (LTCG/STCG), liquidity, minimum investment amount, user's tax bracket, SIP vs lump-sum suitability.

Output: Each instrument gets a composite score. Top-scoring instruments per category enter the optimizer.

Step 4 — Mathematical Optimization (Black-Letterman MVO)

from pypfopt import EfficientFrontier, risk_models, expected_returns

# Step 1: Get historical returns for eligible assets
returns = expected_returns.mean_historical_return(prices_df)

# Step 2: Ledoit-Wolf covariance (more stable than sample covariance)
cov_matrix = risk_models.CovarianceShrinkage(prices_df).ledoit_wolf()

# Step 3: Maximize Sharpe Ratio subject to constraints
ef = EfficientFrontier(returns, cov_matrix)
ef.add_constraint(lambda w: w >= 0.03)        # Min 3% per position
ef.add_constraint(lambda w: w[equity_idx].sum() <= equity_cap)  # Equity cap
ef.add_constraint(lambda w: w[debt_idx].sum() >= min_debt)      # Min debt

weights = ef.max_sharpe(risk_free_rate=0.068)  # 6.8% SBI FD rate
cleaned_weights = ef.clean_weights()

Step 5 — Backtesting + Validation (Before Showing User)

Portfolio is not shown to user until it passes all validation checks:

Walk-forward backtesting: Test portfolio on rolling historical periods (2015–2025). Must beat inflation (6%+) in 80%+ of rolling 3-year windows.

Crisis stress test: Simulate 7 historical crises: 2008 global financial crisis, 2013 taper tantrum, 2016 demonetization, 2020 COVID crash, 2022 rate hike cycle, 2023 US banking crisis, 2024 FII selloff. Portfolio must not lose more than user's stated risk tolerance in any scenario.

Monte Carlo projection: 10,000 simulations of possible market paths over time horizon. Shows P10 (pessimistic), P50 (expected), P90 (optimistic) outcomes at goal year.

Sharpe ratio gate: Portfolio must have Sharpe ratio ≥ 0.5 (acceptable minimum). If optimizer cannot find a portfolio that meets all constraints, it relaxes the least important constraint and retries.

Step 6 — User Approval Flow

✅
Critical rule: Every action requires explicit user approval. Nxance recommends — user decides and authorises. No automated trades. No auto-execution. This is both a regulatory requirement (SEBI RIA) and our core product promise.

For each recommended instrument: NxanceLM explains WHY this instrument, WHAT it contributes to the portfolio, WHAT happens if market falls. User can modify allocation %, approve, or skip each instrument individually. Final confirmation screen requires two taps before any execution request is sent.

Section 05 — Product 3
NxanceLM — Own AI Model
India's own financial AI. Not a ChatGPT wrapper. Zero hallucination. Hindi + English. ₹0 inference cost.

Zero Hallucination Architecture — Why It Matters

What ChatGPT does (WRONG for finance)
User: "Is my portfolio good?"
ChatGPT: "Your portfolio has a Sharpe ratio of 1.2 and XIRR of 14%..."

Problem: ChatGPT invented these numbers. It has no idea what's in the portfolio. This is a hallucination — in finance, this is dangerous.
What NxanceLM does (CORRECT)
Quant engine calculates: XIRR = 11.2%, Sharpe = 0.67, TER waste = ₹4,800
→ Numbers injected into NxanceLM prompt
→ NxanceLM translates to language

NxanceLM never generates financial numbers. It only explains numbers that the math engine already computed. Hallucination is architecturally impossible.

Smart Router — 3-Layer Response System

def get_nxancelm_response(query: str, portfolio_data: dict) -> str:
    
    # Layer 1: Template DB (40% of queries, 0ms response)
    # Pre-built responses for common scenarios
    # e.g., "regular plan issue" → standard explanation template
    template = template_db.match(query)
    if template: return template.fill(portfolio_data)
    
    # Layer 2: Redis Cache (30% of queries, <1ms)
    # If same query asked before → return cached answer
    cached = redis.get(query_hash)
    if cached: return cached
    
    # Layer 3: NxanceLM Generate (30% of queries, 2-4 seconds)
    # Novel queries that need actual model inference
    return nxancelm_model.generate(
        system_prompt=INDIA_FINANCE_SYSTEM_PROMPT,
        user_query=query,
        portfolio_context=portfolio_data  # Numbers from quant engine
    )

Result: 70% of all responses are instant (0–1ms). Only 30% actually use GPU inference. This makes the system fast and cheap to run.

System Architecture
5 system actors, complete data flow, every technology used.

5 System Actors

Actor 1 — User
All 10 Platform Types
Mobile app (iOS + Android) via React Native. Web app via React + Next.js. Same UI/UX, same features across all platforms. Single codebase — one team maintains everything.
Actor 2 — Backend
FastAPI + Python 3.11
6 API routers + WebSocket server for real-time analysis streaming. Celery background workers for nightly re-analysis. All 14 quant engines. gRPC interface to NxanceLM. Hosted on Railway (PoC) → AWS EC2 (Scale).
Actor 3 — NxanceLM
Own AI Model Server
Separate Python service. PyTorch + HuggingFace Transformers. vLLM for efficient inference. Receives portfolio context + query from backend → returns explanation → backend sends to user. Phase 1: runs on CPU (slow). Phase 2: dedicated GPU server.

Supabase (PostgreSQL 16)
All user data, portfolios, health checks, constructions, subscriptions. Row Level Security (RLS) — each user can only see their own data. DPDPA 2023 compliant. AES-256-GCM encryption for sensitive financial data. Supabase also provides Auth (JWT + OTP) and real-time subscriptions.
Actor 5 — Admin
Internal Dashboard
Separate Next.js app. 5 RBAC roles: Super Admin, Engineer, Finance Ops, AI Reviewer, Compliance. Grafana dashboards (performance monitoring), error tracking, user analytics, revenue metrics, NxanceLM quality review.
External Services
APIs + Third-Party
mfapi.in (AMFI data), NSE India API (stock prices), Razorpay (payments), WATI (WhatsApp), Supabase Auth, Firebase Push Notifications, Cloudflare (CDN), CAMS/KFintech (portfolio import).

Section 10
Security Architecture

Authentication

Supabase Auth — JWT RS256 tokens. Access token (15-min TTL) + Refresh token (7-day TTL). OTP via SMS for phone verification. Biometric login (Face ID/fingerprint) using device secure enclave after first login.

Data Encryption

In transit: TLS 1.3 everywhere. No HTTP. At rest: AES-256-GCM encryption for all financial data (holdings, transactions, health check results). Encryption keys stored in separate key management service — not in database.

Row Level Security

Supabase RLS policies ensure every database query is automatically filtered to the authenticated user's data. A bug in application code cannot leak another user's portfolio data — the database enforces isolation at the query level.

DPDPA 2023 Compliance

India's Digital Personal Data Protection Act 2023: Purpose limitation (data only used for what user consented to) · Data minimisation (only collect what's needed) · Right to erasure (user can delete account + all data) · Data localisation (all data stored in India on Supabase Mumbai region).

API Security

Rate limiting: slowapi — max 100 requests/minute per user. Input validation: Pydantic v2 validates every API request body — SQL injection impossible (parameterized queries via SQLAlchemy). CORS: Whitelist of allowed origins only. Payment webhooks: HMAC-SHA256 signature verification on every Razorpay webhook.
