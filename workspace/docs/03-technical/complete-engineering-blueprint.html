Part 06 — NxanceLM (Own AI) — Hybrid 2026 Architecture
NxanceLM — The Third Engine, Woven Through the Other Two
NxanceLM is not a separate, standalone feature — it is the intelligence layer that both the Health Check Engine and Construction Engine call throughout their execution, then also serves the user directly as a chat interface. Three distinct roles, one model.
🧠
NXANCELM'S THREE ROLES
Not a Bolt-On — Woven Into Every Engine Call
Role 1: Inside Health Check
InputRaw structured output from all 11 sub-engines (numbers, flags, scores).
JobTranslates each finding into a plain-English issue card, prioritises which issues matter most for this specific user, drafts the "Fix This" recommendation text.
Result improvementDoesn't just report — cross-references findings (e.g. connects Cost Leak + Tax Efficiency findings into one combined recommendation when they overlap).
Role 2: Inside Construction
InputUser's stated goals (often vague, conversational — "I want to buy a house in 7 years") plus all 14 sub-engines' candidate outputs.
JobConverts vague goals into structured constraints Sub-02 (Goal Decomposer) can use; explains why the QAOA-optimised portfolio was chosen over alternatives.
Result improvementCatches goal ambiguity early (asks clarifying questions) rather than letting Construction Engine silently guess and build a mismatched portfolio.
Role 3: Standalone Chat
InputAny free-form question — "why did the market fall today", "should I invest in gold now", "explain XIRR".
JobGeneral financial Q&A grounded in live market data, independent of any specific engine run.
Result improvementSame model, same weights — the chat "knows" the user's actual portfolio context because it shares memory with the engine-triggered conversations.
This is why NxanceLM's architecture decision (below) matters so much — it is the single model instance handling three very different jobs, so it needs both precision (for engine number-translation) and long-context reasoning (for full portfolio history) and conversational fluency (for chat) — exactly what a hybrid architecture is built for.
⚡
ARCHITECTURE — HYBRID TRANSFORMER-MAMBA-MOE (2026)
Not "Decoder-Only vs MoE" — Both, Combined
Matches NVIDIA Nemotron 3, AI21 Jamba, Alibaba Qwen3.6 — the actual 2026 frontier pattern
Transformer Attention Layers
StrengthPrecise token relationships — exact Rs. figures, XIRR values referenced mid-conversation.
Nxance useShort-context precision: issue-card generation, single-query Q&A, exact number recall.
Mamba / State Space Model (SSM)
StrengthLinear cost — memory constant regardless of context length.
Nxance useLong-context: full 10-year CAS history, multi-year goal-tracking conversations, entire fund prospectus reading.
Mixture-of-Experts (MoE)
StrengthMassive total capacity at small-model inference cost — ~20% of experts activate per token.
Nxance useDomain specialisation: expert cluster for tax/SEBI law, one for portfolio math, one for Hinglish, one for general chat.

Hybrid Layer Pattern — Code Sketch
class NxanceLMHybridBlock(nn.Module): """Every 4th layer = attention (precision). Other 3 = Mamba-2 SSM (long-context, cheap). MoE routing on FFN sublayer throughout.""" def __init__(self, layer_idx, d_model=4096, n_experts=8): self.is_attention_layer = (layer_idx % 4 == 0) if self.is_attention_layer: self.mixer = GroupedQueryAttention( d_model, n_heads=32, n_kv_heads=8, rope_theta=500000) else: self.mixer = Mamba2Layer(d_model, d_state=128, expand_factor=2) self.moe_ffn = MoELayer(d_model, n_experts=8, top_k=2) def forward(self, x, kv_cache=None): x = x + self.mixer(self.norm1(x), kv_cache) x = x + self.moe_ffn(self.norm2(x)) return x # 48 blocks total. Training: DeepSpeed/Megatron-LM + # mamba-ssm CUDA kernels for the SSM layers. # Tokenizer: custom Rust BPE, AMFI-code-preserving, # Hinglish-aware, Rs. formatter.
Why this matters for Nxance specifically: A user's full portfolio history (10 years of CAS statements) can be processed in a single context window instead of chunked/summarised — meaning NxanceLM reasons across the user's entire financial history at once. Directly improves Goal Alignment (HC Sub-03) and Behaviour Analysis (HC Sub-06) accuracy, and lets Construction Engine's Sub-02 (Goal Decomposer) understand multi-year conversational context.
