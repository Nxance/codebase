Open-source Firebase alternative. PostgreSQL database + OTP auth + real-time subscriptions + storage. Ek jagah sab kuch.

Kya karta hai — 4 cheezein ek jagah
PostgreSQL Database: Relational database. Tables, foreign keys, JOINs. Financial data ke liye ACID transactions guarantee karta hai — payment fail hone par partial data nahi likha jaata.
Authentication built-in: Phone OTP (SMS), Email OTP, Google OAuth — sab built-in. No separate auth server. JWT tokens automatically handle hote hain.

Free tier: 500MB database, 50K monthly active users, 2GB bandwidth. MVP ke liye 10,000 users tak free. No company registration needed — personal email se sign up karo.
Kyun PostgreSQL (not NoSQL like Firebase/MongoDB)
Financial data = relational by nature: User → Portfolio → Holdings → Analysis. These relationships matter. NoSQL mein complex queries difficult hoti hain.
XIRR calculation needs exact dates: PostgreSQL DATE type ensures purchase_date exactly stored. MongoDB BSON dates can have timezone issues causing XIRR errors of 0.1–0.5%.
ACID transactions: Atomicity — "INSERT payment + UPDATE tier" either both happen or neither. Critical for payment processing. MongoDB 4.0+ has this but complex to configure.
SQL for analytics: Backend calculation results ko complex SQL queries se analyze kar sakte hain. "Which portfolios have overlap >60%?" — one SQL query. MongoDB mein aggregation pipeline complex.
Firebase comparison: Firebase free tier 1GB Firestore — more storage. But: no SQL, complex financial queries difficult, ACID not guaranteed, no RLS equivalent. Nxance ke liye Supabase better.

F1 — XIRR: Extended Internal Rate of Return
SciPy brentq Newton-Raphson root finder. Exact 11.5364%, not "approximately 11–13%". Handles irregular SIP dates correctly.
Newton-Raphson6 decimal precision
Kyun XIRR (not CAGR or simple returns)
CAGR vs XIRR: CAGR assumes lump sum investment. Indian investors mostly do SIPs (irregular cashflows). CAGR gives wrong answer for SIP investors. XIRR handles every SIP date separately.
Example difference: 3-year SIP portfolio, CAGR says 14%, XIRR correctly says 11.2%. The difference matters when telling user "your portfolio is underperforming."
XIRR Formula
Σ cashflow_i / (1 + r)^(days_i / 365) = 0
r = rate we solve for. cashflow_i = each SIP investment (negative) + current value (positive). days_i = days since first investment. brentq finds r where NPV = 0.
Code + library explanation
Pythoncalculations/xirr.py
from scipy.optimize import brentq
from datetime import date

def calculate_xirr(holdings: list) -> float:
    cashflows, dates = [], []
    today = date.today()
    for h in holdings:
        cashflows.append(-h['invested_amount'])
        dates.append(h['purchase_date'])
    total_current = sum(h['current_value'] for h in holdings)
    cashflows.append(total_current)
    dates.append(today)
    d0 = min(dates)
    days = [(d - d0).days for d in dates]
    def npv(r):
        return sum(cf/((1+r)**(d/365.0))
                   for cf, d in zip(cashflows, days))
    try:
        rate = brentq(npv, -0.99, 10.0, xtol=1e-8)
        return round(rate * 100, 4)
    except:
        return 0.0
scipy.optimize.brentq: Bisection + secant method hybrid. Guaranteed convergence. xtol=1e-8 = 8 decimal place accuracy. More reliable than Newton-Raphson (which can diverge).
Advanced options
Per-fund XIRR: Overall portfolio XIRR + individual fund XIRR. "HDFC Flexicap: 8.2% vs Parag Parikh: 16.4% — why are you keeping HDFC?"
Rolling XIRR: 1yr, 3yr, 5yr XIRR separately. Shows if recent performance improving or declining. Better than single-point XIRR.
SIP-adjusted XIRR: For ongoing SIPs, estimate future cashflows based on SIP amount. "Continuing at Rs 5K/month SIP, projected XIRR = 12.4%"
Alternative libraries: pyxirr (Rust-based, 10x faster), numpy_financial.irr (less accurate). Use scipy.brentq — best accuracy/speed tradeoff.

F2 — Sharpe · Sortino · Jensen Alpha · Beta
Risk-adjusted return metrics. NumPy array operations. Compares portfolio vs Nifty 50 benchmark.
CAPM theoryNumPy vectorized
Each metric explained
Sharpe Ratio
(Rp - Rf) / σp × √252
Rp = portfolio return, Rf = risk-free rate (6.5% RBI repo), σp = daily std deviation. >1 = good, >2 = excellent. Annualized by ×√252.
Jensen Alpha (most important)
α = Rp - [Rf + β(Rm - Rf)]
α > 0 = portfolio beats what CAPM predicts. α < 0 = underperforming given its risk level. Annual α × corpus = Rs opportunity cost shown to user.
Beta calculation explained
Beta: Portfolio's sensitivity to Nifty 50 movements. Beta 1.2 = portfolio moves 12% when Nifty moves 10%. Beta <1 = defensive. Beta >1 = aggressive.
Pythoncalculations/quant.py
import numpy as np
import yfinance as yf

Rf = 0.065  # RBI repo rate 6.5%

# Nifty 50 data (free, yfinance)
nifty = yf.download("^NSEI", period="3y", progress=False)
nifty_ret = nifty['Close'].pct_change().dropna()

# Portfolio weighted daily returns from NAV
port_ret = compute_portfolio_returns(holdings, nav_data)

# Beta = Cov(Rp, Rm) / Var(Rm)
cov_matrix = np.cov(port_ret, nifty_ret)
beta = cov_matrix[0, 1] / cov_matrix[1, 1]

# Jensen Alpha (annualized)
Rp = (1 + port_ret.mean()) ** 252 - 1
Rm = (1 + nifty_ret.mean()) ** 252 - 1
alpha = Rp - (Rf + beta * (Rm - Rf))
Sortino + Max Drawdown
Sortino Ratio
(Rp - Rf) / σ_downside × √252
Only penalizes downside volatility. Better than Sharpe for asymmetric returns (equity MFs). Higher = better downside protection.
Max Drawdown: Largest peak-to-trough decline in portfolio history. "Your portfolio fell 28% from peak to bottom in 2020." Realistic worst-case the user has actually experienced.
Advanced — Rolling Sharpe: 6-month rolling Sharpe ratio. Shows if fund quality improving or declining over time. Line chart in full report.
Advanced — Information Ratio: Alpha per unit of tracking error vs benchmark. Better than Alpha alone for evaluating active fund managers. Phase 2 metric.

F4 — Jaccard Overlap + TER Waste Calculator
Set theory. |A∩B|/|A∪B|. Detects hidden fund duplication. Converts to exact Rs annual waste. Most impactful issue for most users.
Set theoryRs waste exact
How Jaccard overlap works
Jaccard Similarity
J(A,B) = |A ∩ B| / |A ∪ B|
A = Fund 1's top-10 stocks (AMFI monthly disclosure). B = Fund 2's top-10 stocks. J=1 = identical. J=0 = no overlap. J=0.72 = 72% of stocks same.
TER waste formula: waste_rs = jaccard_pct × avg_TER × total_corpus. Example: 72% overlap × 1.5% avg TER × Rs 3,20,000 corpus = Rs 3,456/year wasted on duplicate exposure.
Why this is the #1 issue: 87% of multi-fund portfolios have >30% overlap. Average waste Rs 4,800/year. This is the "Rs 4,800 on free tier" moment that converts users to paying.
Code walkthrough
Pythoncalculations/overlap.py
async def calculate_overlap(holdings, fund_holdings):
    fund_stocks = {}
    for h in holdings:
        code = h['scheme_code']
        stocks = set()
        for item in fund_holdings.get(code, []):
            stocks.add(item['name'].upper().strip())
        fund_stocks[code] = stocks

    codes = list(fund_stocks.keys())
    max_j, best_pair = 0, ('', '')
    
    for i in range(len(codes)):
        for j in range(i+1, len(codes)):
            a = fund_stocks[codes[i]]
            b = fund_stocks[codes[j]]
            union = len(a | b)
            j_val = len(a & b)/union if union > 0 else 0
            if j_val > max_j:
                max_j = j_val
                best_pair = (codes[i], codes[j])
    
    corpus = sum(h['invested_amount'] for h in holdings)
    waste = max_j * 0.015 * corpus # 1.5% avg TER
    return {
        'jaccard_pct': round(max_j*100, 1),
        'ter_waste_rs': round(waste, 0),
        'worst_pair': best_pair
    }
Advanced overlap analysis
Weighted Jaccard: Not just which stocks overlap, but their % allocation in each fund. HDFC Top 100 holds 8% HDFC Bank + Mirae holds 6% HDFC Bank — actual portfolio % duplication more accurate than binary overlap.
Pairwise overlap matrix: For 5-fund portfolios, show 5×5 matrix of all pair overlaps. User sees exactly which funds are redundant.
Sector overlap: Beyond individual stocks. "Your 3 funds are all 35%+ financial sector." Sector concentration risk even without direct stock overlap.
Direct vs Regular plan detector: Fund name contains "Regular" → automatic issue: "Switch to Direct plan of same fund → save Rs 3,200/year." This is free money for user, requires no research.
⚠️ F3 — CVaR Risk Analytics
Conditional Value at Risk. Worst-case loss at 95% confidence. More comprehensive than simple volatility.
CVaR Parametric
CVaR = μ - σ × φ(Φ⁻¹(α)) / (1-α)
μ = mean daily return, σ = std dev, α = 0.05 (95% confidence). If CVaR = 15%: in worst 5% of months, portfolio drops ≥15%.
Crisis simulation: Apply 2008 crash (−52% Nifty) and 2020 COVID (−38%) to current allocation. "If 2008 happened today, your Rs 2.1L → Rs 1.0L temporarily." Shock value creates urgency.

BHB Attribution: how much return comes from asset allocation vs fund selection. HHI concentration index.

HHI = Σ (weight_i)²
HHI = 1 = single fund. HHI = 1/n = equal weight. HHI > 0.5 = over-concentrated. "You have 70% in 1 fund — risky."

import hmac, hashlib, base64

def verify_phonepe(body, x_verify, salt_key):
    # PhonePe uses SHA256 + base64
    check = body + "/pg/v1/pay" + salt_key
    computed = base64.b64encode(
        hashlib.sha256(check.encode()).digest()
    ).decode() + "###1"
    return hmac.compare_digest(computed, x_verify)

Layer 2–4: HMAC + HTTPS + Cloudflare
HMAC-SHA256 for webhooks: Payment gateways sign webhook body with your secret key. You verify → fake webhooks impossible. hmac.compare_digest() = timing-attack proof.
Why compare_digest instead of ==: Regular == comparison: if first byte matches, slightly slower. Attacker can measure time → guess signature byte by byte. compare_digest: always constant time regardless of match point.
HTTPS everywhere: Cloudflare free SSL → nxance.in gets HTTPS. Railway auto-HTTPS for backend URL. Supabase always HTTPS. No plaintext financial data.
Cloudflare free tier includes: DDoS protection (unlimited), CDN (static assets), Bot protection, Rate limiting (basic), SSL, Always-online. Personal account works.

🔢 Monte Carlo Simulation — Better Risk Accuracy
What it is: Instead of single-point CVaR calculation, run 10,000 portfolio simulations with random returns drawn from historical distribution. Probability-based outputs.
PythonMonte Carlo simulation
import numpy as np

def monte_carlo_projection(corpus, xirr, vol, years, n=10000):
    daily_ret = xirr / 252
    daily_vol = vol / np.sqrt(252)
    simulations = []
    for _ in range(n):
        returns = np.random.normal(daily_ret, daily_vol, years*252)
        final = corpus * np.prod(1 + returns)
        simulations.append(final)
    return {
        'median': np.median(simulations),
        'p10': np.percentile(simulations, 10),
        'prob_goal': sum(s>goal for s in simulations)/n
    }
Output: "Probability of reaching Rs 1Cr goal by 2040: 34% at current XIRR. After suggested fixes: 67%." Much more powerful than simple gap calculation.
